\begin{frame}{Four HLA typing runs on the same 1000G short-read cohort, compared pairwise}
  \begin{itemize}\small
    \item \textbf{t1k}: run-t1k directly on raw FASTQs extracted per sample from the 1000G high-coverage CRAMs (\texttt{mhc\_giraffe/t1k}); independent of the graph/phasing steps below
    \item \textbf{Immuannot, old DB}: vg giraffe alignment to leechuck's whole-MHC Minigraph-Cactus graph $\to$ \texttt{vg call} $\to$ WhatsHap read-backed phasing $\to$ \texttt{bcftools consensus} hap1/hap2 FASTAs $\to$ Immuannot against leechuck's frozen IPD-IMGT/HLA 3.55.0
    \item \textbf{Immuannot, new DB}: identical hap1/hap2 consensus FASTAs, re-annotated against a freshly built IPD-IMGT/HLA 3.65.0 (same release T1K uses) -- isolates database-version effects only
    \item \textbf{leechuck\_t1k}: leechuck's own, fully independent run-t1k on the same 2,504-sample cohort (\texttt{1000G\_MHC/t1k}), same file format as t1k above, no pangenome/consensus step at all -- a second opinion on t1k itself
    \item Comparison: unordered allele pairs, truncated to 1-field (allele group) and 2-field (protein) resolution; Immuannot's \texttt{:new} suffix (no exact database match) stripped before truncation, not treated as a literal field; ``overall'' figures pool only the 9 classical HLA genes (A/B/C/DRA/DRB1/DQA1/DQB1/DPA1/DPB1), not the full gene list (see slide 9)
  \end{itemize}
\end{frame}

\begin{frame}{Immuannot's old and new databases agree closely; t1k agrees with Immuannot about half the time}
  \centering
  \includegraphics[width=0.56\textwidth]{gc_overall_concordance.png}
  \begin{itemize}\footnotesize
    \item Immuannot-old vs Immuannot-new: 89\% full-genotype (2-field), 91\% at 1-field, on the 9 classical genes -- expected, since it is the same consensus sequence, only the reference database changed
    \item t1k vs Immuannot (either DB): $\approx$ 49--50\% full-genotype concordance on the same 9 genes -- Immuannot types off a phased short-read consensus (subject to phasing/assembly error), t1k types straight from reads. Confirmed to be a real gap, not a one-off t1k artifact (slide 8)
  \end{itemize}
\end{frame}

\begin{frame}{HLA-DRB1 concordance collapses in every pairwise comparison}
  \centering
  \includegraphics[width=0.82\textwidth]{gc_per_gene_concordance.png}
  \begin{itemize}\small
    \item A/B/C/DPA1/DPB1: Immuannot-old vs Immuannot-new $\ge$ 97\%; t1k vs either Immuannot 42--74\%
    \item HLA-DRB1: only 10--25\% concordance for every pair, including Immuannot-old vs Immuannot-new (same consensus sequence!) -- a paralog-confusable, hard-to-phase locus, not a database-version or typer artifact
  \end{itemize}
\end{frame}

\begin{frame}{How: genotype comparison at 1- and 2-field resolution}
  \begin{itemize}
    \item Truncate each allele string to its first ($k{=}1$) or first two ($k{=}2$) colon-separated fields after the gene, e.g. \texttt{HLA-A*29:02:01:01} $\to$ \texttt{HLA-A*29:02}
    \item Immuannot's \texttt{:new} suffix marks the point past which no exact database allele matched -- \texttt{HLA-A*01:new} is only \emph{1-field}-resolved, not a literal second field of ``new''; stripped before truncation, and a 2-field comparison is skipped (not counted as a mismatch) when fewer than 2 real fields remain
    \item Genotype match: best of the two possible allele-pairings (hap1/hap2 vs allele1/allele2 order is arbitrary between pipelines); full match requires 2/2 alleles to agree
    \item Script: \texttt{analysis/gc\_typing\_concordance.py}; tables in \texttt{results/tables/gc\_*.tsv}
  \end{itemize}
\end{frame}

\begin{frame}{70--88\% of Immuannot's classical-gene calls are novel (\texttt{:new}), consistent with imperfect short-read phasing}
  \centering
  \includegraphics[width=0.62\textwidth]{gc_novel_uncalled_rate.png}
  \begin{itemize}\footnotesize
    \item t1k rarely leaves a classical gene untyped (3--9\%, DPA1/DRA higher at 21--24\%); leechuck\_t1k shows the same rates gene-for-gene, confirming this is a property of the reads, not a t1k-run artifact
    \item Immuannot flags a novel allele on 70--88\% of A/B/C/DQB1/DPB1 calls, old and new DB alike -- the consensus sequence itself, not the database, is the limiting factor (matches the pipeline's own documented caveat: WhatsHap phasing can leave chimeric/ambiguous consensus for highly polymorphic genes)
  \end{itemize}
\end{frame}

\begin{frame}{Two independent t1k runs agree far more with each other than either does with Immuannot}
  \centering
  \includegraphics[width=0.56\textwidth]{gc_leechuck_t1k_comparison.png}
  \begin{itemize}\footnotesize
    \item leechuck\_t1k vs this pipeline's t1k: 80\% full-genotype concordance, 9 classical genes -- driven down mainly by HLA-DRA/DPA1 (low-polymorphism), the other 7 genes are 82--93\%
    \item leechuck\_t1k vs Immuannot (either DB): 49--50\% -- essentially the same gap as this pipeline's own t1k shows vs Immuannot (previous slide)
    \item Conclusion: swapping in an independent t1k run barely moves the t1k-vs-Immuannot number -- the discordance is about Immuannot/consensus quality, not which t1k run is used
  \end{itemize}
\end{frame}

\begin{frame}{Neither t1k run touches the pangenome graph -- only Immuannot does}
  \begin{itemize}\small
    \item \texttt{mhc\_pipeline.sbatch} labels its own t1k step ``independent of the graph/phasing steps above'' (line 144) -- both t1k runs (this pipeline's and leechuck's) type directly off raw FASTQs, no giraffe/vg/consensus step involved
    \item The \emph{only} pangenome-derived arm in this whole comparison is Immuannot, which types the vg giraffe $\to$ \texttt{vg call} $\to$ WhatsHap $\to$ \texttt{bcftools consensus} sequence
    \item So ``did the pangenome alignment improve typing'' really means: does Immuannot-on-pangenome-consensus beat t1k? Checked directly against real published truth genotypes on the next slide (Gourraud et al. 2014 1000G HLA diversity panel, Sanger/SSO typing, 955 samples also in this cohort)
  \end{itemize}
\end{frame}

\begin{frame}{When Immuannot commits to a 2-field call, it's as accurate as t1k -- but it commits far less often}
  \centering
  \includegraphics[width=0.4\textwidth]{gc_truth_concordance.png}
  \begin{itemize}\footnotesize
    \item Tied on accuracy: t1k 98.8\%, Immuannot 98.5\% (either DB) full-genotype match to published truth (2-field, 5 classical genes)
    \item Denominators aren't comparable though: t1k resolves 90\% of its truth-eligible calls to 2-field (n=1843); Immuannot only 33\% (n=613) -- the rest are \texttt{:new}/low-resolution calls (slide 7), uncheckable, not wrong
    \item So: pangenome alignment + phasing doesn't demonstrably change per-call accuracy -- it costs \emph{resolution/coverage}, not correctness
  \end{itemize}
\end{frame}

\begin{frame}{Correction: an earlier pass compared against a stale precomputed table}
  \begin{itemize}\small
    \item First attempt used \texttt{leechuck/hla/typing/conc\_partial/data/conc\_t1k\_vs\_published.tsv} (412 samples, 5 genes) as ``leechuck's t1k'' -- it showed only 86\% agreement with this pipeline's t1k, and disagreements looked like a coverage/read-extraction effect (traced, incorrectly, to the 16 GRCh38 chr6 MHC ALT contigs missing from this pipeline's read extraction)
    \item Checking that hypothesis directly on a discordant case (HG00097, HLA-B) found \emph{zero} reads split onto an ALT contig at that locus, and identical read depth/content between the two extractions -- the ALT-contig story does not hold up
    \item Root cause of the confusion: \texttt{conc\_t1k\_vs\_published.tsv} predates leechuck's current, live \texttt{1000G\_MHC/t1k/} run (all 2,504 samples) and simply disagreed with leechuck's \emph{own current} output for the same sample/gene -- it was never a fair comparison to begin with
    \item Re-run against the live \texttt{1000G\_MHC/t1k/} directory instead (previous slide): agreement jumps to 80\% on classical genes (94--99\% on A/B/C/DRB1/DQB1 individually); the ALT-contig slides have been removed
    \item Lesson: always check a precomputed table's timestamp/provenance against the pipeline that's supposed to have produced it, especially when it disagrees with a live re-derivation
  \end{itemize}
\end{frame}

\begin{frame}{Take-home}
  \begin{itemize}\small
    \item \textbf{Pangenome alignment did not improve typing accuracy here} -- against real published truth, Immuannot-on-pangenome-consensus (98.5\%) and t1k (98.8\%) are statistically tied when Immuannot actually commits to an answer. The pangenome/phasing arm's real cost is \emph{resolution}: it only reaches a checkable 2-field call 33\% of the time vs. t1k's 90\%
    \item Immuannot's database version (3.55 vs 3.65) barely matters (89--91\% agreement, classical genes); the consensus sequence quality from graph alignment + WhatsHap phasing is the real bottleneck, especially for A/B/C/DQB1/DPB1 (70--88\% flagged novel) and DRB1 (concordance collapses even DB-vs-DB)
    \item t1k-vs-Immuannot discordance ($\approx$ 49--50\%, classical genes) is real and confirmed by a second, fully independent t1k run -- not an artifact of one t1k invocation
    \item t1k remains the more practically useful call for benchmarking: same accuracy as Immuannot when both can be checked, but usable on far more calls
    \item Open: revisit DRB1 specifically (worst locus everywhere, including DB-vs-DB) once Immuannot-new-DB finishes the full cohort; understand why HLA-DRA/DPA1 show more t1k-run-to-run disagreement than A/B/C/DRB1/DQB1 do
    \item Script, figures, tables: \texttt{pangenome-bh26/hla/analysis/gc\_*.py}, \texttt{results/figures/gc\_*.png}, \texttt{results/tables/gc\_*.tsv}
  \end{itemize}
\end{frame}
